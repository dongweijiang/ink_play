# 《墨痕登塔》第 0 轮技术风险与开发拆分

> 本文只冻结工程边界、风险对策和第 1～9 轮任务，不包含正式游戏代码。

## 1. 架构边界

- `src/domain`：纯数据模型与不可依赖 pygame 的规则对象。
- `src/systems`：战斗、地图、奖励、存档、配置、绘图分析等用例；只通过明确接口访问随机数和持久化。
- `src/states`：把输入翻译成命令，把领域状态翻译成可绘制视图；不拥有唯一游戏数据。
- `src/ui`：布局、控件和绘制；不判断伤害、奖励或胜负。
- `src/ai`：识别协议、Mock、在线适配器和响应校验；只返回固定标签与置信度，不返回游戏效果。
- `data`：稳定 ID 的内容配置；加载后转为带类型的数据对象。
- `RunState`：单一局内事实来源，包含种子/RNG 状态、生命、金币、牌组、地图、访问记录、当前印记、待用护印、题签/并印上下文、稀有补偿值、彩蛋限制、战斗/绘图统计、配置版本和存档版本。笔势、强印、显印次数属于单场战斗状态，不写回永久角色数据；不存在“已选流派”字段。

依赖方向固定为：`states/ui -> systems -> domain`；`systems -> ai` 只依赖识别器协议。`domain` 不得反向导入 pygame、UI、网络或文件路径。

## 2. 文件树说明

总体沿用需求中的文件树。第 1 轮建立骨架时做两项必要补充：

- 在 `src/states` 增加 `rest_state.py` 与 `drawing_result_state.py`，因为冻结状态表中有独立 `REST` 和 `DRAWING_RESULT`，不能把它们暗藏在地图或绘图页面。
- 增加 `src/resources.py`，统一图片、字体、音频路径与缺失资源占位，避免资源职责散落在 UI 或常量模块。

不为尚未实现的功能批量创建空模块；各轮只创建当轮实际使用或含有明确接口的文件。

## 3. 技术风险清单

| 风险 | 可能影响 | 概率/影响 | 冻结对策 | 验证轮次 |
|---|---|---|---|---|
| pygame UI 与战斗规则耦合 | 无法无窗口测试，修复易破坏界面 | 中/高 | 规则层禁止依赖 pygame；UI 只提交命令 | 1～2 |
| 状态切换发生在事件处理中 | 旧状态继续更新、回调写错页面 | 中/高 | 帧末统一切换；状态令牌与请求 ID 校验 | 1、7 |
| 在线 API 阻塞主线程 | 窗口假死、系统判定未响应 | 高/高 | 后台工作线程；主线程轮询不可变结果；支持取消 | 7 |
| API 返回未知/恶意文本 | 越权生成效果或解析崩溃 | 中/高 | 固定标签白名单、严格 schema、本地映射、忽略图中文字指令 | 7 |
| API Key 泄漏 | 隐私与比赛交付事故 | 低/高 | 环境变量或内存临时输入；日志脱敏；存档字段白名单 | 7、9 |
| 存档写入中断/版本漂移 | 一局丢失、继续游戏崩溃 | 中/高 | 临时文件写入、原子替换、单备份、版本迁移/拒绝策略 | 5 |
| Python 随机状态不可跨变更重现 | 继续游戏后地图或结果变化 | 中/中 | 地图预生成并保存；关键随机结果保存；测试同版本重现 | 5～6 |
| 配置单条损坏 | 启动闪退或引用悬空 | 中/高 | 分文件 schema 校验、收集错误、跳过无引用坏项；严重错误页 | 3 |
| 中文字体在不同系统缺失 | 方框字、布局溢出 | 高/中 | 随发行版携带许可明确的中文字体；开发期回退与占位 | 1、8 |
| 高 DPI/窗口缩放 | 点击坐标错位、画面模糊 | 中/中 | 1280×720 逻辑画布，统一 letterbox 坐标变换 | 1、8 |
| 绘图统计误伤认真玩家 | 核心创新带来负面体验 | 中/高 | 低置信度与至少两项低投入条件同时满足；首次保护 | 6 |
| 复杂卡牌复制/延迟效果出错 | 顺序不一致、存档难恢复 | 中/中 | 效果队列与卡牌实例 ID；按冻结顺序测试 | 2～3 |
| 手柄热插拔/音频设备失败 | 局部功能导致程序退出 | 中/中 | 设备事件重建；音频初始化失败转静音 | 8 |
| 打包漏数据或动态依赖 | 测试机无法启动 | 高/高 | PyInstaller 清单、干净机器冒烟、启动日志与资源自检 | 9 |
| 资源规模或每帧加载 | 卡顿、内存超标 | 中/中 | 资源缓存；加载只发生在状态进入或预加载阶段 | 1、8～9 |
| 范围膨胀 | 无法完成完整一局 | 高/高 | 严守轮次与不做清单；优先完整流程与绘墨 | 全程 |

## 4. 开发任务拆分与完成定义

### 第 1 轮：工程骨架

- 建立实际需要的目录、依赖、入口和日志初始化。
- 建立 1280×720 逻辑画布、60 FPS 主循环、窗口/全屏切换与 letterbox。
- 建立显式状态协议和帧末状态切换；实现 BOOT、主菜单、设置、暂停和安全退出。
- 建立资源管理器、中文字体回退、图片占位和 pytest 框架。
- 完成定义：可启动；菜单/设置可来回；演示空场景可暂停返回；窗口关闭安全退出；无正式战斗。

### 第 2 轮：纯规则战斗引擎

- 建立 Actor、Card、Deck、Effect、Combat 模型与战斗命令。
- 实现抽牌、洗牌、费用、目标、伤害、格挡、延迟效果、敌人意图、回合和胜负。
- 以最小文本模拟器跑完一场战斗；补齐规则顺序测试。
- 完成定义：无 pygame 环境下测试通过，同种子战斗可复现；不制作正式 HUD。

### 第 3 轮：数据驱动内容

- 定义并验证卡牌、敌人、BUFF JSON schema；实现容错加载和引用完整性检查。卡牌 `design_tags` 只用于统计与测试，奖励生成器不得据此分池。
- 录入扩充稿冻结的 50 张卡牌、8 种普通敌人、2 种精英、1 个 Boss、6 种印记和遭遇表。
- 将规则引擎从硬编码样例切换为配置对象，补配置与数值测试。
- 完成定义：新增普通卡牌只需数据；单条坏配置给出可定位错误；严重引用错误进入可理解错误。

### 第 4 轮：战斗界面

- 实现战斗 HUD、手牌扇形/横排、目标选择、点击与拖动、敌人意图和数值预览。
- 实现占位动画、结束回合、牌堆查看、胜负与卡牌奖励页。
- 完成定义：只用鼠标可打完一场战斗；界面数值与规则测试一致。

### 第 5 轮：地图、事件和存档

- 实现 9 层模板、可达性约束、节点状态、3 个事件、休息和简化商店。
- 实现 `RunState` JSON、版本字段、临时写入+替换、自动备份、损坏/不兼容处理。
- 新建/继续/自动保存贯通；地图与事件 RNG 可复现。
- 完成定义：关闭进程后从同一地图位置继续，不能通过重载重掷结果。

### 第 6 轮：绘图与 Mock 识别

- 实现 256×256 画布的画笔、橡皮、撤销、清空、提交和可选跳过。
- 统计绘制时间、笔画、覆盖、点/直线与重复空白；实现可复现 Mock。
- 实现置信度分流、候选确认、本地 BUFF 映射、弱灵感和彩蛋限制。
- 完成定义：完全离线走完战后绘图并影响下一战；边界与限制测试通过。

### 第 7 轮：真实 LLM 接口

- 固化 `DrawingRecognizer` 和 `RecognitionResult`；在线适配器使用后台线程。
- 实现隐私同意、临时 Key、12 秒超时、最多一次退避重试、错误分类和离线降级。
- 严格 JSON/标签校验；迟到响应、取消、离开页面均不能修改旧状态。
- 完成定义：用模拟网络覆盖成功、认证、断网、限流、超时、非法 JSON、未知标签；均可继续游戏。

### 第 8 轮：输入、美术和音频

- 完善键鼠、焦点式手柄、热插拔和触屏单指映射。
- 替换关键占位美术，加入可授权字体、BGM/SFX、独立音量与静音降级。
- 检查分辨率、全屏、DPI、文字可读性和缺失资源占位。
- 完成定义：关键流程可纯鼠标完成；手柄可操作关键菜单；缺音频设备/资源不崩溃。

### 第 9 轮：测试、平衡和打包

- 执行完整流程、规则覆盖率、异常、性能和长时冒烟；仅基于数据调整平衡。
- 完成 README、设计/技术/操作/测试/许可证 PDF、截图、演示脚本和交付目录。
- 用 PyInstaller 构建 Windows 版本，在无 Python 的干净 Windows 环境验证。
- 完成定义：从交付包启动并完成一局；无秘密、缓存、无授权素材或大量日志。

## 5. 关键接口冻结

以下是接口语义，不是本轮代码：

- 状态：`enter(context)`、`handle_event(event)`、`update(dt)`、`draw(surface)`、`exit()`；切换请求交由状态机帧末执行。
- 识别器：输入 PNG `bytes`，输出结构化 `RecognitionResult`；业务层永远不接收自由生成的效果。
- 配置加载：返回“有效条目 + 诊断列表”，由启动策略决定继续还是进入错误页，不静默吞异常。
- 存档：序列化字段白名单；任何 API Key、原始绘图字节、线程对象、pygame 对象均禁止进入存档。
- 随机源：系统通过注入的随机接口取值，测试可固定种子；UI 不直接调用全局随机函数。

## 6. 第 0 轮退出条件

- 完整一局的入口、节点、战斗、绘墨、Boss 与结算已有明确顺序。
- 做与不做的范围清楚，时间不足时有削减优先级。
- 50 张卡牌、8 普通/2 精英/1 Boss、6 印记和 3 事件有稳定 ID 与初值。
- 数值取整、触发时机、胜负、混沌和低投入彩蛋可以直接转成测试。
- 每个后续轮次有独立完成定义；第 1 轮不会提前实现战斗。
